# T20d-b: sending the cloud copy

> **For agentic workers:** built by this session task by task (superpowers:executing-plans), with a self-review at the end, the owner's standing choice. Steps use checkboxes.

**Goal:** every company's encrypted backup reaches the cloud by itself once a day when its data changed, each copy's key also sealed to the platform's recovery key, and the owner can open a copy offline with his own tool.

**Architecture:** the cloud copy is D-069's backup zip plus `recovery.json`. The phone works out the copy's SQLCipher key (PBKDF2-HMAC-SHA512, 256,000 rounds, over the password and the file's salt) in a background isolate, checks that the key opens the copy, and seals it to the public half in `RECOVERY_KEY`. A `CloudSender` per open company sends through the `backup` function of T20d-a (start, signed upload, finish). The sealing and the owner's tool share one file with no Flutter import, so the tool runs with `dart run`.

**Tech stack:** Flutter, `cryptography` (Pbkdf2, X25519, Hkdf, Chacha20.poly1305Aead), `archive`, `sqlite3` on SQLite3MultipleCiphers, `supabase` (functions, storage `uploadBinaryToSignedUrl`).

**Spec:** `docs/superpowers/specs/2026-11-14-t20d-cloud-backup-design.md`; the cloud's contract: `docs/superpowers/plans/2026-11-14-t20d-a-cloud.md`. Decisions D-069, D-072, D-075, D-076.

## Global constraints

- Never call the copy end-to-end encrypted (DATA-08). The words say the platform can open it.
- The recovery key's private half never in the app, the repo, `.env` or the server. `RECOVERY_KEY` in `.env` is the public half only.
- A file saved or sent from the Backup page carries no `recovery.json`.
- A build without a valid `RECOVERY_KEY` makes no cloud copy and says the cloud backup is unavailable.
- Sent by itself on open and on coming back to the front, at most once a day (24 hours after the last copy that went), only when the data changed; with the plan ended too. A failure changes nothing on the phone and shows on the Backup page.
- 50 MB (52,428,800 bytes) at most; a larger copy is not sent and the page says so.
- `replace` only on the owner's choice on the Backup page.
- The backup password is asked once at signup, typed twice, and can't be skipped.
- Roman Urdu and English strings in both `.arb` files; `flutter gen-l10n`.

## Review focus

1. A key that does not open the copy sealed anyway: the platform would hold a copy it can't open. The phone checks the derived key opens the copy before sealing (Task 1 test).
2. The company closing or a restore swapping the file while a copy is being made: the swap and the logout wait for the send to settle (Task 3).
3. Coming back to the front many times while offline: at most one attempt an hour after a failure, so the phone does not rebuild the copy on every switch (Task 3 test).
4. A new phone whose cloud copy came from the old phone: auto-send never replaces it, it asks, and keeping this phone's data needs a confirm (Tasks 3 and 4 tests).
5. The tool's key file written inside the repo: refused (Task 2 test).

## Task 1: the sealed key (`recovery.dart`, `backupBytes`)

**Produces:**
- `const recoveryFile = 'recovery.json'`, `const copyKeyRounds = 256000`
- `bool isRecoveryKey(String base64Public)`: 32 bytes of base64.
- `Future<Uint8List> copyKey(String password, Uint8List data)`: PBKDF2-HMAC-SHA512, 256,000 rounds, 32 bytes, salt the first 16 bytes of `data`.
- `bool opensWithKey(String path, Uint8List key)`: opens with `PRAGMA cipher = 'sqlcipher'; PRAGMA legacy = 4; PRAGMA key = "x'<hex>'"` and reads `sqlite_master`.
- `Future<Map<String, Object>> sealCopyKey(List<int> key, String recoveryPublic, {required String tenantId, required String sha256})` → `{v: 1, alg: 'X25519-HKDF-SHA256-ChaCha20-Poly1305', epk, nonce, ct, mac}` (base64). Ephemeral X25519; HKDF-SHA256 over the shared secret, salt `labour-app recovery v1`, info `epk ‖ recoveryPublic ‖ "<tenant>:<sha256>"`; ChaCha20-Poly1305 with AAD `"<tenant>:<sha256>"`, tenant lower-cased.
- `Future<Uint8List> openCopyKey(Map<String, dynamic> sealed, SimpleKeyPair pair, {required String tenantId, required String sha256})`, throws `RecoveryRefused` on any mismatch.
- `backupBytes(password, {work, now, String? recoveryKey})`: with a key, adds `recovery.json` after checking the derived key opens the copy.

In `test/backup_test.dart`: a cloud copy has `manifest.json`, `data.db`, `recovery.json`, passes `checkBackup`, and its key opens it; the existing test keeps a saved file at exactly two entries.

## Task 2: the owner's tool

**Produces** in `recovery.dart`:
- `Future<Map<String, Object>> lockRecoveryKey(SimpleKeyPair pair, String passphrase)` and `Future<SimpleKeyPair> unlockRecoveryKey(Map<String, dynamic> file, String passphrase)`: PBKDF2-HMAC-SHA512, 600,000 rounds, 16-byte salt, ChaCha20-Poly1305; the file keeps `public` in the clear.
- `bool insideGitCheckout(Directory dir)`: any parent up to the root holds `.git`.
- `Future<Uint8List> reopenCloudCopy(Uint8List copy, SimpleKeyPair pair, String newPassword, Directory work)`: an ordinary backup (no `recovery.json`, manifest's `sha256` renewed) locked with `newPassword`.

`tool/recovery_key.dart`: `make <folder>` (refuses a folder inside a git checkout or an existing key file; passphrase twice, 12 characters or more, hidden on a terminal; writes `recovery-key.json`; prints only the public half) and `open <key file> <copy.zip> <out.zip>` (passphrase, the new password twice; prints the company id and the copy's date).

- [ ] Tests: the locked file unlocks to the same pair, a wrong passphrase is refused, the private bytes are not in the file; `insideGitCheckout` true under a folder with `.git`, false in a plain temp folder; a reopened copy passes `checkBackup` with the new password, is refused with the old one (`wrongPassword`), has no `recovery.json` and the same workers.

## Task 3: sending (`Account.sendCloudCopy`, `CloudSender`, AppRoot)

**Produces:**
- `AccountProblem` gains `otherPhoneCopy`, `notOwner`, `tooLarge`; `problemOf` maps `other_phone_copy`, `not_owner`, `too_large`, `too_many`.
- `Account.recoveryKey` (from `RECOVERY_KEY`); `Future<DateTime> Account.sendCloudCopy(String tenantId, Uint8List bytes, {required bool replace})`: one operation id; start, upload to the signed URL as `application/zip` unless the file arrived, finish.
- `bool get Account.hasSession`.
- `String cloudCopyKey(String tenantId)` in `backup.dart`; `deleteTenant` forgets it.
- `typedef CloudView = ({DateTime? lastAt, AccountProblem? problem, bool sending})`.
- `class CloudSender({required Account account, required FlutterSecureStorage storage, required String tenantId, required TenantDatabase Function() db, required Future<Directory> Function() work, DateTime Function() clock, int limit = 52428800})` with `CloudView get view`, `Stream<CloudView> watch()`, `Future<void> load()`, `Future<void> sendIfDue()`, `Future<void> sendNow({bool replace = false})`, `Future<void> settled()`, `Future<void> dispose()`. The record `{at, mark, problem}` in secure storage; `mark` is the outbox's count and latest time.
- `sendIfDue` skips: no password, no session, the last copy under 24 hours old, the mark unchanged, a failure in the last hour, or a standing `otherPhoneCopy` or `notOwner`.
- `cloudSenderProvider` (null without a valid `RECOVERY_KEY` or accounts) and `cloudViewProvider`. AppRoot makes the sender, sends after the licence's first refresh and on `AppLifecycleState.resumed`, and waits for `settled()` before closing the file in a swap or a logout.
