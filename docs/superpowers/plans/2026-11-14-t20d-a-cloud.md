## The contract (what T20d-b and T20d-c call)

Storage: private bucket `backups`, 50 MB, `application/zip`, no policy for the app. A path is `<tenant id>/<copy id>.zip`, written once.

Table `public.cloud_backups`: `id`, `tenant_id`, `device_id`, `file_path`, `size_bytes`, `started_by`, `started_at_utc`, `finished_at_utc` (null until the file is seen), `keep_until_utc` (set on a daily copy), `source_operation_id`. The owner reads their company's rows.

Postgres, called as the user:

- `backup_start(p_tenant_id, p_device_id, p_size_bytes, p_operation_id, p_replace default false) returns jsonb` `{path, arrived}`. The owner, on their first phone that is on. Refuses a size over the bucket's limit, more than 20 starts a day, and a company whose latest copy came from another phone unless `p_replace`. A retry returns the same path; `arrived` says the file is already in storage.
- `backup_finish(p_tenant_id, p_operation_id) returns timestamptz`. The file must be in storage; its size is read there. With an add-on period active the copy is a daily copy, kept the plan's `backup_keep_days`; an earlier daily copy of the same Dubai day gives way. Then every copy that is not this one and not a daily copy inside its days leaves the list and joins the removal queue.
- `backup_download(p_tenant_id, p_device_id, p_backup_id) returns text` (the path). The owner, on their first phone that is on, with an add-on period active.

Postgres, for the server only: `backup_removals_due() returns text[]`, `backup_removals_done(p_paths text[])`.

The `backup` function, POST with the user's session, JSON body:

| `action` | Body | Reply |
| --- | --- | --- |
| `start` | `tenant_id`, `device_id`, `size_bytes`, `operation_id`, `replace` | `{path, token}`; `token` is null when the file already arrived |
| `finish` | `tenant_id`, `operation_id` | `{finished_at}`, then the due files are removed from storage |
| `download` | `tenant_id`, `device_id`, `backup_id` | `{url}`, good for 60 seconds |

Refusals: `{error}` with `sign_in` 401, `bad_request` 400, `too_large` 400, `too_many` 429, `not_owner`, `not_registered`, `phone_off`, `other_phone`, `other_phone_copy`, `addon_needed` 403, `no_copy` 404, `not_arrived` 409, `server` 500.

The add-on: `subscriptions.kind` is `plan` or `addon`; `payment_slips.covers` is `plan`, `plan_addon` or `addon`; `submit_slip` takes `p_covers` last, default `plan`. The licence gains `addon_until`. `plans.backup_keep_days` is 30; `platform_settings.support_contact` is typed by the owner.

Deleting an account: the newest copy waits 60 days in `private.backup_removals` with the company's id and the email; the rest go at once.

## Review focus

- A changed app asking for another company's copy, or for its own without the add-on.
- A second start while the first upload is still running: the first file must not stay in storage for ever.
- A copy finished twice, or finished with no file.
- A kept copy of a deleted account removed before its 60 days.
- One slip for the plan and the add-on: the two periods' money adds up to what the bank received.
