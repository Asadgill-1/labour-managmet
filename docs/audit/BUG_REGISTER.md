# Bug register

Severity: Critical = severe compromise or widespread data loss. High = major workflow failure or serious access or data-integrity defect. Medium = meaningful failure with a workaround. Low = minor.

## BUG-001: a release APK cannot reach the internet

- **Severity:** High. Release blocker for anything from T19b on.
- **Stages:** T19 (AUTH-01), T20c, T20d (DATA-06), T21 (BILL-05).
- **Where:** `apps/mobile/android/app/src/main/AndroidManifest.xml`.
- **Expected:** a release build can sign up, log in, fetch its licence and send its cloud copy.
- **Actual:** the main manifest never declared `android.permission.INTERNET`. Only `src/debug` and `src/profile` do, for the Flutter tool. No plugin adds it. Every cloud call in a release build fails as if offline. After 7 days with no licence check the company's entries lock (D-074).
- **Evidence:** `build/app/intermediates/merged_manifests/release/processReleaseManifest/AndroidManifest.xml` (built 2026-11-01) lists no INTERNET permission, while the debug one does. `git log -S"android.permission.INTERNET"` on the main manifest finds nothing. Every recorded run was a debug APK, the Windows build or a widget test, which is why nothing caught it.
- **Root cause and confidence:** the template's manifest was kept when the cloud arrived in P4. High confidence.
- **Repair:** the permission added to the main manifest. Regression test `apps/mobile/test/android_manifest_test.dart`.
- **Risk:** none known; debug builds already had it.
- **Status:** FIXED. `test/android_manifest_test.dart` passes, and its one check fails on the manifest as it was (`git show HEAD:...AndroidManifest.xml | grep -c INTERNET` gives 0). A release APK built on 2026-11-16 (`flutter build apk --release`, 85 MB) lists `android.permission.INTERNET` in its merged manifest. Still open: a release APK logging in on a phone.

## BUG-002: an amount typed with too many digits throws or wraps round

- **Severity:** Low. Needs 14 or more digits typed or pasted into an amount field.
- **Stages:** T09 (CALC-01), every form that takes money.
- **Where:** `packages/domain/lib/money.dart`, `parseAed`.
- **Expected:** anything that is not a usable AED amount returns null, so the form says so.
- **Actual:** the pattern took any number of digits. 20 digits made `int.parse` throw inside a form validator; 17 to 18 digits overflowed when turned into fils and came back as a wrong figure.
- **Evidence:** `packages/domain/test/money_test.dart`, "parseAed turns an amount too long to hold away", failed before the change (`Expected: null, Actual: 1000000000000000`).
- **Repair:** at most 13 digits of dirhams. `dart test` in `packages/domain`: 151 passing after.
- **Risk:** amounts of AED 10 trillion or more are refused.
- **Status:** FIXED AND VERIFIED by the domain tests, and by the full `flutter test` re-runs after it (`VERIFICATION.md`).
